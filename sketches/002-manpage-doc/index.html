klaridian — generate an instrumented MCP server from an OpenAPI spec

Synopsis
copy
$ npx klaridian generate --spec <file> [--plugin otel] [--transport stdio|streamable-http]
--spec path to an OpenAPI 3.x or Swagger 2.0 document --plugin observability plugin to wire in (otel, posthog) --overlay x-klaridian-mcp overlay for curated tool metadata
Description

klaridian reads an OpenAPI specification and emits a stateless, TypeScript Model Context Protocol server — one tool per operation — with observability plugins wired at the registerTool boundary. The output is plain, readable source, not a generated binary: read it before you trust it with real credentials next to an autonomous agent.

How it works
1parseOpenAPI 3.x / Swagger 2.0, converted transparently via getToolsFromOpenApi().
2curateexclude, rename and tag operations so agents see a clean tool catalog.
3emitSDK v2, protocol 2025-11-25, stdio or streamable-http transport.
4instrumentOTLPTraceExporter spans on every tool call — Datadog, Grafana, any OTLP backend.
Options
--exclude-tags, --exclude-ops
remove operations from the generated tool surface before emission.
--transport streamable-http
emit a network-reachable server instead of stdio; required for OAuth 2.1 resource-server mode.
--plugin otel
wrap every tool call in an OpenTelemetry span; diagnostics to stderr, never stdout.
