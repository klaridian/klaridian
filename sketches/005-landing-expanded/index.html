Building an MCP server today means writing it twice.

Once for the tools. Once more, by hand, for tracing, product analytics, and tool curation — repetitive work every MCP server author redoes from scratch.

Datadog, PostHog, Sentry, and Grafana already ship MCP servers of their own — but those let an agent query those platforms, not automatically instrument a new server you're building. klaridian closes that gap: pick a plugin at generation time, get a server that's already instrumented.

How it works

01

Parse

Any OpenAPI 3.x document — Swagger 2.0 is converted transparently before parsing.

$ klaridian generate --spec ./api.yaml
02

Curate

Exclude, rename, or tag operations so agents see a clean tool catalog — not your whole API surface by default.

$ --exclude-tags internal,admin --overlay ./overlay.yaml
03

Emit

A stateless @modelcontextprotocol/server project (SDK v2, protocol 2025-11-25) — plain, readable TypeScript source, not a generated binary.

$ --transport streamable-http --architecture tools
04

Instrument + analyze

OTel spans on every tool call, product-analytics events via PostHog/Amplitude/Mixpanel — wired at generation time, not bolted on later.

$ --plugin otel or --plugin posthog

Two ways to expose your API

Pick per generation — one tool per operation, or a typed client for large specs

DEFAULT

Tools architecture

  • One MCP tool per OpenAPI operation
  • Byte-identical tool names to your operationIds
  • Best for small-to-medium specs (tens of operations)
  • Validated 1:1 against Stripe (452 tools) and a real production API
CODE-MODE

Typed client + execute_code

  • Two tools total: execute_code, search_docs
  • Model writes TypeScript against a typed, Zod-validated client
  • Runs sandboxed in an isolated Deno subprocess
  • Built for large specs — avoids hundreds of chatty tools

Read it before you trust it

An MCP server runs with real operational credentials next to an autonomous, non-deterministic caller. That's a materially higher trust bar than a normal backend a human calls deliberately — so klaridian's generator, and everything it emits, is open source and auditable by default.

FAQ

Is klaridian production-ready?
It's a working v0, pre-1.0. Core generation, curation, and both plugin families are tested end-to-end (real npm install + build + stdio JSON-RPC drives), but the API surface may still change before 1.0.
What license do generated servers ship under?
MIT by default (--license mit), Apache-2.0 as an option. Every generated server ships a real LICENSE file and package.json license field — --license none opts out but prints a warning.
Can I use more than one plugin on the same server?
Not on the current emitter — one plugin per generated server today (otel, or one of posthog/amplitude/mixpanel). Multi-plugin composition was supported by an earlier pipeline and is a tracked follow-up.
Does it support Python / FastMCP?
The generator itself is TypeScript/Node-only. A separate, native FastMCP middleware ships for Python product-analytics (PostHog) — see the docs for details.
