# Market research (Aug 30, 2026)

Raw output from 4 parallel research passes, conducted to inform the differentiation-path decision recorded in ARCHITECTURE.md sections 21-24 and PLAN.md section 5. Kept verbatim (not cleaned up) as the primary source these decisions cite — future re-reads of the summarized decisions should be able to trace back to what was actually found, not just the conclusion.

- `2026-08-30-mcp-ecosystem-trajectory.md` — where the MCP protocol/ecosystem is heading strategically (Anthropic/AAIF roadmap, SEPs in flight, platform vendor moves).
- `2026-08-30-developer-pain-points.md` — real developer complaints/feature requests from Reddit, Hacker News, GitHub issues on major MCP projects. This is the source for the "tool bloat is the strongest validated pain point" finding that drove the section 24 tool-curation decision.
- `2026-08-30-competitive-fleet-landscape.md` — competitive/funding landscape for MCP observability, analytics, and fleet-management tooling. This is the source for concluding the hosted correlation/fleet layer idea (PLAN.md section 4) has early competitors but isn't crowded yet — though adjacent governance/gateway space is well-funded.
- `2026-08-30-enterprise-adoption-blockers.md` — what large organizations say they need to run MCP in production (identity/SEP-990, security incidents, governance spend) — mostly validates a different category (governing existing servers) than mcpforge's current one (generating new servers).

Each file is a raw subagent JSON output (`report_markdown` + `top_3_signals`) saved as-is — not reformatted into clean prose, since the goal here is traceability to sources, not readability. If you need the polished takeaways, read ARCHITECTURE.md sections 21-24 and PLAN.md section 5 instead; come here only to verify a specific claim against its original research pass.

# MCP server development best practices & landscape (Sep 2, 2026)

Second batch of 4 parallel research passes, prompted by a direct question about whether a code generator or a runtime framework is the right architecture for mcpforge, and what marketplaces (claude.ai, ChatGPT) actually require. Unlike the Aug 30 batch, these are written as source-cited markdown reports (not raw JSON), with every claim tagged verified/inferred/unverified and a Sources section with access dates. They reflect the MCP `2026-07-28` spec revision (stateless; sessions/handshake removed; DCR deprecated in favor of CIMD; SEP-414 trace context landed), which post-dates everything in ARCHITECTURE.md up to section 35.

- `2026-09-02-mcp-spec-transports-and-auth.md` — what the current spec requires of a SERVER: transports, the OAuth 2.1 resource-server obligations (RFC 9728 PRM, audience validation, no token passthrough), what stdio servers must NOT do, and 17 implications for an OpenAPI→MCP generator.
- `2026-09-02-mcp-marketplaces-and-connector-requirements.md` — per-marketplace listing requirements (Anthropic Connectors, ChatGPT Apps, MCP Registry, Docker, Smithery, Glama, Cursor/VS Code, Copilot Studio, Cloudflare, Google, aggregators): open-source requirement, transport, auth, hosting, review, fees, tool-design gates. Ends with a "listed everywhere" checklist.
- `2026-09-02-mcp-server-tooling-landscape.md` — SDKs, frameworks, OpenAPI→MCP generators, hosting, OAuth/IdP providers, observability and QA tools with licenses, pricing and hard adoption metrics pulled from GitHub/npm/PyPI APIs. Includes "standalone codegen vs runtime framework: what the market does" and "gaps nobody fills well".
- `2026-09-02-mcp-server-best-practices.md` — tool design (with cited tool-count studies), security (OWASP MCP Top 10, supply chain), operations, open-source distribution, marketplace-ready multi-tenancy, community pain points, and a 27-item Must/Should/Nice production checklist.
